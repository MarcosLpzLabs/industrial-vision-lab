## Error Git Commit

Error:

cannot run vi

Causa:
Git intentaba abrir vi para introducir el mensaje.

Solución propuesta:

git config --global core.editor "code --wait"

---

## Error Python

Error:

ModuleNotFoundError: No module named 'services'

Estructura:

industrial-vision-lab/
├── apps/
└── services/

Import utilizado:

from services.camera_service import CameraService

Causa:
El script se estaba ejecutando como:

python apps/camera_info.py

y Python tomaba apps como raíz.

Solución explicada:
Crear:

apps/**init**.py
services/**init**.py

y ejecutar:

python -m apps.camera_info

# Feedback recibido sobre el diseño

Problema detectado:

La clase ejecuta demasiada lógica dentro de **init**().

Actualmente:

CameraService()
↓
inicializar_camara()
↓
cap_video()
↓
bucle infinito

Esto significa que simplemente instanciar el objeto ya ejecuta toda la aplicación.

Se explicó que:

Un constructor debería:

* inicializar recursos.
* guardar configuración.

Un constructor NO debería:

* lanzar bucles infinitos.
* abrir interfaces.
* ejecutar la lógica principal.

# Concepto que estamos aprendiendo ahora

Arquitectura de software.

Separación de responsabilidades.

La idea es que:

CameraService se encargue únicamente de:

* abrir cámara.
* leer frame.
* obtener FPS.
* obtener resolución.
* liberar recursos.

Y que la aplicación principal decida:

* mostrar vídeo.
* ejecutar IA.
* guardar imágenes.
* procesar datos.
